# 在阿里云那台小机器上更新

## 平时更新就用这个

```bash
cd ~/Duet && bash deploy/update.sh
```

它做四件事：**停服务 → 生成 Prisma Client → 限制内存构建 → 启动**。

## 为什么不能直接 `git pull && npm run build && systemctl restart`

两个坑，都跟这台 2G 内存的机器有关：

1. **构建时 `.next` 正在被重写，而服务还在读它**
   → 页面一直转圈、加载不出来，构建没结束就一直卡着。
2. **`next build` 会把 2G 内存吃满**
   → 机器 swapping、SSH 都连不上（banner exchange timeout 就是这个症状）。

所以正确的顺序必须是「先停服务，再构建，最后启动」。代价是那几分钟页面打不开。

## 第一次先加 swap（强烈建议）

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

加完之后构建会慢一点，但不会把机器压死。

## 构建卡死了怎么救

```bash
# 1. Ctrl+C 中断构建

# 2. 看看到底谁在吃内存
free -h
ps aux --sort=-%mem | head

# 3. 兜底：清掉半成品再重建
cd ~/Duet
sudo systemctl stop duet
rm -rf .next
NODE_OPTIONS="--max-old-space-size=1536" npx next build
sudo systemctl restart duet
```

## 判断服务是不是活着

```bash
systemctl status duet
journalctl -u duet -n 50 --no-pager
curl -I http://127.0.0.1/login
```

`curl` 能返回 200 就说明应用本身没问题，外面打不开是网络或浏览器缓存。
