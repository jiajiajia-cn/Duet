# 习惯打卡 / 签到类产品功能与机制调研报告

> 调研时间：2026-10；用途：软件需求文档（PRD）前置研究
> 方法说明：优先抓官方帮助中心/官方仓库/应用商店官方文案。**Habitica Wiki（Fandom）、stickK 官网与帮助中心被 Cloudflare/网络拦截**，改用 Habitica 官方 FAQ 仓库镜像与 stickK 的 App Store 官方描述；**知乎、Reddit 不可达**，用户吐槽改用 Hacker News 评论 API 与应用商店评分。滴答清单帮助页为 JS 渲染、抓取为空，其习惯模块细节标注为"待验证"。

## 一、结论速览

1. **两种范式**：纯习惯派（Loop/Streaks/小日常）是"习惯 + 频率 + 连续天数"；游戏化派（Habitica）是"任务（习惯/日常/待办/奖励）+ 价值 + 生命值"，打卡即造成伤害或获得金币。
2. **"一天"的边界必须可配**：Streaks 有 Start of Day（默认 0:00，设为 2:00 则一天为 02:00–次日 01:59），Habitica 有 Custom Day Start。
3. **补卡既是付费点也是作弊点**：Streaks 可改任意历史日期，小打卡把补签卡做成**年费会员权益、1 个圈子每月 4 次**，Habitica 干脆不补卡、只给"暂停伤害"。
4. **多人机制三种形态**：Habitica 的 Party（≤30 人、伤害共担、副本）、stickK 的 Referee（监督人一票否决）、小打卡/鲸打卡的圈子训练营（助教点评 + 积分排行榜）。
5. **金钱惩罚留存高但投诉最狠**：Beeminder 押金阶梯 $0→5→10→30→90→270→810→2430→7290 可封顶；用户吐槽"压力反而加重拖延"。

## 三、习惯数据模型（建议字段）

- `name`（≤40 字）、`icon`（Streaks 600+ 图标，小日常新增 23 个医疗健康图标）、`color`
- `habit_type`：`positive | negative | dual | measurable`（Habitica 明确正向/负向/双向三型）
- `frequency_type`：`daily | weekly_n | specific_weekdays | every_n_days | monthly_day | period_n`（Streaks 的"周期任务"以周/半月/月/年计，连续按周期数而非天数）
- `frequency_value`：`n`（每周 N 次）、`weekdays[]`（1–7）、`interval_days`（Loop/Streaks 上限 60）、`month_day`（1–31 或"最后一天"）
- `target_count`（每日次数）、`target_value` + `unit` + `goal_type`（`at_least`/`at_most`；Loop 的"至多"型当天永不算完成，这条边界必须写进规则）
- `notes`（Streaks 支持每日笔记）、`tags[]`、`category_id`
- `start_date`（Habitica 有坑：午夜到 CDS 之间创建的任务起算日应为用户视角"昨天"，官方 issue #5525 修过）
- `count_in_stats`（是否计入完成率/连续；Loop 的暂停、跳过需要它，否则完成率被永久污染）
- `reminder`：`time`、`weekdays[]`、`mode`（`fixed`/`auto`，Streaks 默认 auto）
- `streak_current`、`streak_best`、`streak_unit`（天/周/月）、`total_checkins`、`archived_at`（必须软删）

## 四、打卡交互与"一天"边界

**一键打卡**：小日常是"翻牌 + Click 音效"的即时反馈；Streaks/Loop 支持在通知或小组件直接完成（Loop 官方描述可在通知内打卡或忽略）。

**同日多次**：Habitica 习惯可无限点"+"；Streaks 用"每天需完成 N 次"；底层建议 `(habit_id, local_date, seq)` 唯一键，按 `target_count` 截断计分。

**补打卡规则对比**：

| 产品 | 规则 | 动机 |
|---|---|---|
| Streaks / Loop | 可改任意历史日期（Loop 还能补备注） | 单机无排行榜，作弊无收益 |
| 小打卡 | 补签卡仅年费会员，1 个圈子每月 4 次 | 补卡=会员权益 |
| Habitica | 不支持，只能"暂停伤害"或把频率改成每 0 天 | 有组队与排行，补卡破坏公平 |
| Beeminder | 不支持，只能提"legit check"申诉 | 押金模式下补卡=送钱漏洞 |

**建议**：`backfill_window` 默认 T+2（最长 7 天）、`backfill_quota` 普通 3 次/月、会员 4 次/圈/月；补卡记录打 `is_backfill=true`，不计入"当日首次打卡"类成就，并在他人可见列表里显示"补"角标。

**时区与边界**：存 `local_date`（按用户时区/打卡日换算）+ `tz_offset`；`day_start_hour` 默认 0、可选 0–6。**不要用服务器 UTC 日期归档**，跨时区旅行按打卡发生时的用户时区。窗口型打卡（如早起 05:00–08:00）建议窗口外"可记录但不计分"。

## 五、多人 / 监督机制

- **Habitica Party**：上限 30 人、下限 1 人，**待接受邀请也占名额**（29+1=30）；队长可设管理员；队员漏做日常→全队掉 HP；副本进度次日统一结算；"寻找队伍"名单 7 天不登录自动移出。
- **Habitica 团队计划**：仅队长/管理员能建共享任务；指派后其他人不能完成；共享日常按队长每日起始时间统一重置，漏做不掉血只掉颜色。
- **stickK**：本人 / **Referee（核验报告，平台"以其说法为准"）** / Supporters（打气）三层角色；报告可选每日、每周或期末一次。
- **鲸打卡/小打卡**：机构端有打卡课程、作业课程、解锁课程；督学含打卡提醒、点评、点赞、精选、课程通知、积分排行榜、作业展示与导出；营销含结课证书、日签长图、积分商城。
- **可见性建议**：字段级三档 `private/circle/public`，默认"完成状态可见、备注与图片私密"。Habitica 2023 年关停酒馆与公会，官方理由之一就是公共空间的主动内容监管成本——圈子应"邀请制 + 人数上限"。

## 六、积分 / 奖励与防作弊

- **Habitica**：金币（做任务）+ 宝石（付费、挑战奖品，订阅者可用金币兑且每月上限 +2 直到 50）；任务越红完成收益越高；死亡惩罚极重（掉 1 级 + 清空金币 + 掉 1 件装备），治疗药水 25 金币回 15 HP，升级回满。本质是**用损失厌恶替代积分通胀**。
- **鲸打卡**：积分 + 排行榜 + 积分商城，积分来自打卡与互动，可兑换。
- **其余**：不设可消费货币，只做连续天数 + 完成率 + 徽章（iBetter 100+ 勋章、小日常"当日全完成解锁成就卡片"）。
- **streak break**：Streaks 漏一天归零，但"每周三次"类任务在休息日不清零；Loop 用指数衰减习惯分，长期连续后漏几天不清零。建议**双指标并存**：前端展示严格连续（有冲击力），复盘页展示习惯强度（半衰期 7 天）。
- **防作弊**：补卡留痕并限次；计量型异常值（一天 200 杯水）标红不入榜；排行榜用"完成率 × 打卡天数"而非绝对次数；图片打卡校验 EXIF；**不要给可自证行为发可交易货币**。

## 七、通知与提醒

- **定时**：Loop 每习惯独立时间；滴答支持多闹钟与重复；时光序有独立喝水提醒。
- **智能时间**：Streaks 默认"Automatic Times"，按你历史上完成该任务的时间推断——建议 v1 就做（取近 14 天完成时间中位数）。
- **错过提醒**：Habitica 在 CDS 前由 cron 结算并扣血；建议"临期提醒"（21:00 仍未打卡且当日必做 → 一条温和提醒），每日上限 2 条。
- **渠道**：推送 / 邮件 / 微信服务号模板消息 / 小程序订阅消息（一次订阅只能发一条，需按"本周还差 2 次"这类汇总消息设计）。
- **免打扰**：`quiet_hours` 默认 23:00–08:00，支持单习惯静音；连续 7 天忽略自动降频而非继续轰炸。

## 八、统计与回顾

- 必备：日历热力图、当前连续、最长连续、完成率（分母用"应做次数"而非自然日）、周/月报告。
- 进阶：按时段分布（Streaks）、计量趋势 + 月度累计（iBetter）、目标进度条（时光序）。
- **反面案例**：Habitica 官方 FAQ 承认"没有任务数据随时间变化的可视化，只能导出"，用户复盘只能自己拉 CSV——这是它最持久的差评来源。
- 导出：Loop 支持 CSV 与 SQLite，Streaks 支持 CSV 导入导出，Habitica 在设置-站点数据导出。建议字段 `date, habit, value, unit, note, is_backfill, source`。

## 九、常见失败点与用户吐槽

1. **游戏化过重**：HN 用户称"RPG 元素没打动我，喜欢的是和朋友一起打 Boss 这件事"；另一人"用 Habitica 是因为朋友开心，不是因为游戏"。
2. **可靠性**：Habitica 被指"无离线支持、服务器频繁宕机"——打卡是每天一次的低频动作，失败一次就丢连续。
3. **数据不可视**：Habitica 无图表（官方承认），而图表正是 Loop 的核心竞争力。
4. **押金引发焦虑**：HN 用户称 Beeminder"让我压力剧增、反而更拖延，还亏了钱"；UI 被评"笨重、术语太极客"。
5. **补卡公平性**：小打卡补签卡限会员且限次，免费用户断链即流失；Habitica 玩家则抱怨漏一天就掉血、惩罚过重。
6. **评分侧写**：stickK iOS 仅 2.6/5（26 个评分），远低于小日常 4.78/5（55 万评分）与 Streaks（买断制、App Store 编辑推荐）——"惩罚型"满意度天然低于"陪伴型"。

## 十、对我方产品的可借鉴设计建议（含取舍理由）

1. **双指标并列：`streak` + `habit_score`**。取舍：严格连续有链式心理，但断链即弃是最大流失点；UI 只显示连续天数，复盘页显示 0–100 的习惯强度（指数衰减、半衰期 7 天），断链不清零。
2. **"一天"可配 + 补卡有配额**。取 Streaks 的 `day_start_hour`（默认 0，可选 0–6）并在首页提示"今天截止于 02:00"；补卡 T+2、每月 3 次、留标记且不进"全勤"。取舍：全开放会让排行榜与训练营失效，全禁止会劝退凌晨用户。
3. **模型直接支持计量型与负向型**（`target_value/unit/goal_type`，`at_most` 当天永不算完成）。取舍：只做布尔打卡会丢掉"喝水 8 杯""少抽 3 根"这类高留存场景。
4. **监督关系做成独立实体**：`supervision(supervisor_id, supervisee_id, scope, can_verify, can_remind, started_at, ended_at)`，参考 stickK 的 Referee 与 Habitica Party。取舍：Referee 的"一票否决"在国内易生纠纷，建议"可催办、可点评、不可代打卡、不可否决"，裁定权交给系统规则。
5. **惩罚分级，不做金钱押金**：漏打卡→掉积分→掉等级→连续 3 次缺卡则移出榜单（而非踢出）。取舍：押金涉资金合规与支付牌照，且 stickK/Beeminder 的投诉集中在扣款争议与焦虑；用社交可见性+积分损失替代，风险更低。
6. **提醒默认"自动时间" + 21:00 一次温和兜底**。取舍：固定时间在作息漂移后必然失效，自动时间几乎零成本。
7. **圈子邀请制、内容默认私密**，只公开"今日是否完成"。取舍：Habitica 因公共空间内容监管成本关停酒馆/公会，这是可预见的内容审核负债。
8. **v1 就做统计与 CSV 导出**。取舍：成本极低，却是用户对"数据主权"的最低要求，也是 Habitica 最持久的差评点。
